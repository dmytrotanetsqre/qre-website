Services no longer mounts it. The visible canvas is a fixed Geist Mono 0/1 grid at the hero ASCII cell (14px, letter-spacing 0.5, 12px below 1024). Cells never move, rotate, or scale; each flips 0↔1 on its own slow clock. Three.js draws the shape as a solid mesh — key light plus rim, faces near brightness 0.62, rims toward white — into a small offscreen buffer. Each frame samples that buffer one pixel per cell (`getImageData`, the ASCII renderer's path) and uses the brightness as the cell's alpha, so cells outside the shape stay off and rotation reads as light moving across the still grid. The six shapes are meshes normalised to the same size. A service change crossfades the two meshes over 0.9s (in-out cubic, a slight scale); a newer target replaces the in-flight one from the current weights, so fast scrolling never queues. The mesh yaws once every 18s. `createCrystal`, `crystal-lab.html`. **Rule: if it's not 100% clear which option a prompt applies to, ask the user before making changes.** Don't assume the most recently edited option, and don't apply a change to several options unless explicitly told to.

## Workflow

- The GitHub repo `dmytrotanetsqre/qre-website` is the source of truth.
- The site is published by GitHub Pages from `main` at `https://dmytrotanetsqre.github.io/qre-website/` (a sub-path), so every URL must stay relative (`../assets/...`), never root-absolute.
- Work happens in cloud sessions on branches, merged through pull requests.
- Each step is logged in `docs/PROJECT_LOG.md`; open questions go to `docs/open-questions.md`.
